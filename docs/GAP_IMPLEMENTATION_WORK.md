## Review requirements

- Read the architecture and the source document for each gap. Use the local BN C++
  reference for units and rules. Check whether old claims are already superseded.
- Player features need a discoverable real UI, save/load handling, cancellation and
  failure behavior, and item/energy conservation through the existing APIs.
- Match the current adaptation decisions. Additive integration in shared files;
  implementations and tests belong in dedicated files where practical.
- No fake achievements, removed assertions, blanket test unskips, unexplained
  content stand-ins, or documentation edits that disguise incomplete implementation.
- Typecheck and appropriate regression tests must pass. Interactive/visual changes
  need inspected screenshots and real-input verification; performance work needs
  measured evidence. Builds/browsers use the documented resource wrapper.
- Lead reviews diffs and evidence, requests corrections, and merges accepted
  commits into the integration branch. Root-checkout local changes are preserved.
